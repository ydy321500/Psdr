### 必须遵守的 UI 架构约束

- `Psdr.UI.dll` 统一提供颜色、字体、间距、控件样式和公共界面组件。业务模块通过合并 `Themes/Theme.xaml` 使用；不在各个页面复制通用样式。模块差异较大时保留独立界面。
- 总体采用浅色背景、白色内容面、清晰层级与适当留白；导航、查询、列表、编辑和详情保持统一。先做典型页面的实际视觉检查，再批量迁移。不能仅凭 XAML 或编译结果判断美观。
- 主窗口、导航、列表、编辑、选择器和单据页面使用 MVVM。纯提示/确认弹窗允许轻量代码，但涉及输入、校验或业务状态的弹窗仍使用 ViewModel。
- 所有窗体使用自定义标题栏和统一的右上角按钮样式，不使用系统原生窗体标题栏；纯确认弹窗也遵守这一点。
- Prism 负责容器、模块注册和 ViewModel 绑定；主窗口由 ViewModel 管理可同时打开、切换、关闭的页签。页面代码隐藏只保留视图自身的技术性操作，不承载数据库调用或业务决策。
- 风格和控件应服务于高频 ERP 操作：快捷键、扫码输入、表格密度、状态识别、批量操作和错误反馈都需要实际操作检验。

## 第一阶段：新版功能等价

1. **建立基线**：逐个记录新版菜单入口、可执行操作、数据库表、权限条件、打印输出和异常路径。将“有菜单但无实现”标为缺口，不算已完成功能。
2. **建立公共骨架**：登录、代理上下文、主窗口、导航、权限服务、统一异常与日志、数据库连接工厂、列表和编辑组件。共享的界面与算法先抽共用能力，差异明显的红包和商城流程独立实现。
3. **迁移基础资料**：产品、字典、客户、供应商、销售人员、用户、仓库、条码。用一套列表/编辑/选择框架承载不同实体。
4. **迁移业务主链**：入库、出库、盘点、销售开单、订单查询、退货、价格和财务。每项对照旧版的输入、状态变更与库存、应收结果。
5. **迁移附属功能**：代理管理、产品映射、商城设置、操作日志和新版实际存在的其他功能。报表以实际可用的 FastReport 集成结果为准。
6. **等价验收**：对每项记录“原版输入及结果 → 新版输入及结果”，覆盖正常、取消、库存不足、重复条码、退货、跨代理访问和断线重试。源码存在不等于流程已完成。

## 第二阶段：补齐旧版全部功能

先按旧版 `UI` 目录逐页审计，形成“保留 / 已由新版覆盖 / 合并 / 重做”的明细，再实施。当前初步差异包括：

## 当前验证边界

新版 `LoginForm` 在统一登录页中先用本机代理号查询主库，再校验代理库业务账号；特殊 `sys` 账号通过额外的密码分支进入管理员界面。该实现把主库 SQL 凭据硬编码在客户端。重写版采用统一入口：`sys` 直接验证 `Psdr_Master.dbo.AdminUser` 中同名账号的散列密码并进入代理管理界面，无须先配置代理号；普通账号只使用本机保存的代理号连接对应代理库并校验 `User`；停用代理时管理端禁用其 SQL 登录，客户端无需主库查询凭据。建库仍要求运行客户端的 Windows 身份具备 SQL Server 管理权限。`Psdr.Admin` 现为桌面端引用的类库，不再提供独立 EXE 和第二套登录页。新建主库管理员 `sys` 的默认密码为 `123456`，仍按 PBKDF2-SHA256 加盐保存；旧主库仅有 `admin` 时，初始化脚本将账号改名为 `sys` 并保留原密码。普通代理 SQL 账号没有建库权限。

新版 `FrmAgentEdit` 原先只向主库 `Agent` 表登记资料；每个代理的数据库与 SQL 用户由管理员手动创建。现在管理端开通代理时先在 `Psdr_Master` 登记 Pending，再创建以代理 GUID 命名的数据库和 SQL 登录，将该登录只映射到自己的库并赋予 `db_datareader`、`db_datawriter`，初始化当前实现的 `User`、`StoreHouse` 表及业务管理员，最后验证连接并标记 Ready。失败保留 Failed 状态，可重试；旧代理记录标记 Unverified，不能直接执行自动建库。管理端还支持代理资料编辑和停用/启用 SQL 登录。主库初始化入口是 `scripts/Initialize-AdminDatabase.ps1`；管理端连接默认使用本机 `.` 和 `Psdr_Master`，可用 `PSDR_ADMIN_SQL_SERVER`、`PSDR_ADMIN_DATABASE` 指定其他实例及主库。远程服务器默认验证证书。本机 `.` 允许信任本机证书。普通客户端不包含建库权限。

登录页的“代理设置”只输入代理号，并用当前 Windows 用户的 DPAPI 加密保存在本机 `%LOCALAPPDATA%\Psdr\agent-number.dat`；再次启动自动读取，只有首次配置或更换代理才需要输入。连接规则与新版 `SqlsugarHelper.GetDbClient` 对齐：代理号同时作为数据库名、SQL 用户名和密码；服务器地址由部署环境变量 `PSDR_SQL_SERVER` 指定，不让业务用户编辑连接字符串。客户端只连接该代理库，不提供独立开发库的连接入口。代理号兼作密码存在泄露风险，正式部署前应更换为独立密码并保持设置页只输入代理号。业务账号登录已接入当前代理库 `User` 表；代理停用由管理端禁用专用 SQL 登录，正式凭据交付仍待实现。生产连接默认验证 SQL Server 证书，客户端不会自动建表或改表。

数据库只有主库与代理库两类。`Psdr_Master` 保存代理登记信息，每个代理的 GUID 同时是其分库名。代理库表和视图的定义归档于 `database/tenant`，由管理模块在开通时初始化。早期验证用的独立 `Psdr_Dev` 库及其启动脚本已移除；本地验证可临时创建代理，完成后清理该代理的主库记录、分库及 SQL 登录。
